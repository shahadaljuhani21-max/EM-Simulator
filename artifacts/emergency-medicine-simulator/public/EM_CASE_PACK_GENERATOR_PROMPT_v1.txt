Use the existing schema fields; do not invent unsupported properties:
- case.interactionModel: set to "action_based" for every newly generated case and author all clinical-review metadata required by the schema.
- case.responseMode: set to "keyword_written" for every newly generated case. The learner types a written response to each step.prompt instead of choosing from a visible action list.
- step.prompt: a neutral clinical question that can be answered in a short written response.
- step.guidance: reasoning prompt, focus and useful hint for Guided; available only on request in Independent; hidden in Challenge. Guide thinking without revealing the correct choice. Example: “Think about the immediate threats in the ABCDE assessment. What needs to be checked or treated before obtaining a full history?”
- action.classification: optimal, acceptable, incorrect or dangerous.
- action.answerKeywords: hidden, specific words or phrases that map a written response to this action. Add this to every non-fallback action at every step, including clinically wrong or dangerous actions, using phrases that clearly express that action. Include common synonyms and abbreviations. Do not use broad or overlapping terms; keywords must be unique within each step. Matching is whole-phrase, case/accent/punctuation-insensitive, not semantic.
- action.responseFallback: set true on exactly one additional action per step. This action is selected when no answer keyword matches. It must be classified incorrect, not unsafe, unnecessary or critical, have no answerKeywords, reveals or patientChanges, and have a neutral consequence. Route it to the next safe decision (or terminal disposition). Never worsen the patient merely because an answer did not match.
- action.feedback: WHY the mapped action's classification applies, important investigation/treatment interpretation, better alternatives and a teaching point where appropriate. Show this explanation after every submitted answer in Guided, Independent and Challenge.
- action.consequence, reveals and patientChanges: realistic observable information and responses only, never coaching or answer keys. Place requested history, examination and investigations in action.reveals rather than automatically disclosing all results in step.findings.
- action.nextStepId: shared progression. Encode appropriate prioritization and sequence through the graph. Explain premature/delayed actions in feedback where clinically relevant, and preserve realistic poor-choice consequences.
- endOfCaseSummary: clinical reasoning, ordered idealApproach, essential actions to check for omissions, unsafe choices and better alternatives, learningPoints and references. The review shows the actual ordered decisions. Static omission advice must be conditional, not falsely personalized.

Keyword scoring contract:
- Every step in every new case must have exactly one neutral responseFallback action and answerKeywords on every other action. The learner does not see action choices or keywords before submitting.
- Any one positive answer keyword mapped to an optimal or acceptable action makes that step correct. One response earns at most one correct mark, even if it contains multiple matching terms. The engine prefers optimal, then acceptable, if more than one action matches; incorrect/dangerous matches are considered only when no correct action matches.
- Phrases close to negation (for example “not,” “without,” “avoid,” or “withhold”) are not counted as positive matches. Keep keywords affirmative and clinically specific. Ensure a right phrase does not appear in a dangerous action's keywords.
- Use the action's feedback as the explanation for its mapped keyword response. Guided, Independent and Challenge display the answer result, mapped action and explanation immediately after every submitted answer. Challenge must not reveal matched keywords, correctness labels or feedback before the learner submits that response. Clinical consequences and patient changes may still be shown after submission.
- If no keyword matches, commit the authored neutral responseFallback, record the answer as incorrect, and continue the case. The fallback consequence must state what is clinically observed without adding an invented deterioration or newly available finding.
- A keyword match is a simple answer-recognition signal, not proof of understanding or a validated clinical assessment. Include clinically meaningful terms and synonyms, and disclose this limitation in the case pack instructions and review.
